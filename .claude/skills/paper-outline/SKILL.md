# Paper Outline & Story Architecture

Apply the shared [working-language policy](../shared-references/research-autonomy.md#working-language) to internal work and user reports.

For contribution-type structure and evidence requirements, consult [paper-type-routing.md](../shared-references/paper-type-routing.md).

## Mode routing

Load only the module that matches the user's request and contribution type:

| Need / Contribution type | Module guide |
|---|---|
| Technical / method paper logical skeleton (thinking-template table, Technique vs. New Problem positioning, 4-point consistency check) | [modules/tech-paper-template/GUIDE.md](modules/tech-paper-template/GUIDE.md) |
| Benchmark / evaluation paper (five-pillar framework, completeness audit, 6-part Intro chain, Section 2–7 skeleton) | [modules/benchmark-paper-template/GUIDE.md](modules/benchmark-paper-template/GUIDE.md) |
| Finding, sharpening, evaluating, or rewriting the scientific story across manuscripts, abstracts, pitches, or discussions | [modules/good-story/GUIDE.md](modules/good-story/GUIDE.md) |

## Scope boundary

- Deliver an outline, story critique, or thinking-template table according to the request.
- Full section or manuscript prose drafting belongs to [paper-writer](../paper-writer/SKILL.md).
- Preserve explicit evidence gaps at proposal stage; never fabricate results to fill an outline.
